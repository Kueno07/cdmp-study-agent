# Data Quality — Ch.13 (11%)
| Concept | Testable angle | Common confusions |
|---|---|---|
| DQ Management cycle | Plan → Deploy → Monitor → Act | Confusing with DMAIC or Shewhart |
| DQ dimensions | Accuracy, Completeness, Consistency, Validity, Uniqueness, Timeliness, Integrity | Accuracy (vs reality) vs Validity (vs rules); Consistency vs Uniqueness |
| Dimension trade-offs | Improving one can degrade another | Dimensions are independent |
| DQ Firewall | Prevention — blocks bad data at entry | Monitor (after-load) or remediation |
| Parsimony Rule | Minimal rules, maximum impact | Data minimization or budget |
| DQ requirements source | Steward + business consumers | IT/DBA defines requirements |
| Monitoring vs Auditing | Continuous measurement vs periodic program | Interchangeable |
| Root cause analysis | Fix the process, not just the data | Cleanse repeatedly without fixing source |
| Data profiling | Discover structure, content, anomalies | Confusing with cleansing |
